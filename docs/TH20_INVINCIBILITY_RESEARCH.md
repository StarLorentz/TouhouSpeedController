# TH20 无敌入口调查

对象：本机 `th20.exe`，SHA-256
`E6C4371E214C95DD4DBCAAF6818C79C5E89881270F65B62B8C3C965B65851E2D`。
以下地址是该 EXE 首选基址 VA，只读反汇编所得，尚未在关卡中验证补丁。

## 已确认的路径

- `0x4F84A1` 调用 `0x4E1250` 并传入 `-1`，从 `GlobalsSide+0xB8`
  扣除一条残机。其外层函数从 `0x4F8420` 开始，还执行射击、石头等
  状态处理；它属于死亡处理，并非最早的弹幕碰撞判定。
- `0x4F794D` 是对 `0x4F8420` 的调用点；前面先检查玩家计时状态。
  直接跳过扣残机或让这个函数返回，可能使玩家仍留在死亡状态。
- `0x4FF490` 读取 `GlobalsSide+0xE8` 的判定范围比例；`0x4F905B`
  和 `0x4F924A` 两处把其返回值用于碰撞半径计算。thprac 也有
  `th20_hitbox_scale_fix`，把该函数固定返回 100。这证明它控制判定
  大小，但不能据此把比例设为 0 并宣称完全无敌；还需分清受击、擦弹
  和道具路径，确认半径为零时的边界条件。
- 更早的 `0x4F86F0` 同时由 `0x4F8FCF`、`0x4F91B2`、`0x4F944B`
  三条碰撞路径调用。函数内部设置玩家状态与计时器，并处理受击效果，
  比扣残机函数更接近 TH16 使用的受击状态转换入口。本机 EXE 在该处
  的起始字节为 `55 8B EC 83 EC 1C`。

## 实验候选与下一次验证

开发版已针对这个精确 EXE 指纹加入可恢复的候选补丁：启用前验证上述
六个原始字节，临时把入口首字节改为 `RET`；关闭、换进程和退出时恢复。
这只证实代码位置和可逆写入设计，尚不代表关卡中的无敌效果已验证。
下一步需要实际关卡分别验证敌弹受击、擦弹、射击、Bomb、切关和关闭
恢复；若出现漏判或异常，应先关闭功能并退出游戏，再重新分析路径。
TH19 暂不纳入本轮。
