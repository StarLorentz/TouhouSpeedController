# 练习功能开发路线

本路线用于把东方变速器逐步扩展为通用练习工具。每个阶段单独验证，
已经发布的 v0.1.1 在新功能稳定前保持不变。

## 不可跳过的安全规则

1. 通过游戏编号、文件名、PE 架构和 SHA-256 同时识别游戏版本。
2. 未命中已验证配置时只显示信息，不读取或写入游戏内存。
3. 写入代码前保存原始字节；关闭功能、游戏退出或工具退出时恢复。
4. 每个配置记录来源、支持的 EXE 哈希、验证项目和验证日期。
5. 汉化版、Steam 版和日文原版分别验证，不能仅凭文件名共用地址。
6. 练习功能产生的录像可能不同步，界面必须明确提示。

## 架构

- **界面层（C# / WinForms）**：自动识别进程，接受用户输入，展示当前值和支持状态。
- **控制协议**：延续现有命名管道方式，使用明确的读取、设置、冻结、恢复命令。
- **游戏适配层**：每个游戏版本拥有独立配置，包含哈希、地址、指针链和补丁。
- **进程内模块**：仅在必须拦截扣除或受击逻辑时使用；简单数值优先从外部安全读写。
- **变速模块**：继续使用 OpenSpeedy，与练习功能保持可独立启用和恢复。

## 阶段 1：版本识别地基（当前阶段）

- 建立第三方代码和许可证说明。
- 固定最初参考的 thprac 提交版本。
- 提供只读 EXE 指纹工具。
- 记录本机 TH16 日文版和汉化版的已知哈希。
- 不修改游戏内存，不改变当前程序行为。

## 阶段 2：TH16 资源读写

- 2A：只读显示当前残机、炸弹、炸弹碎片和 Power。
- 2B：日文版人工确认读取正确后，加入有限范围写入和回读校验。
- 输入合法范围内的值并立即写入。
- 对地址和数据范围做二次验证，未知版本禁用按钮。

阶段 2A 调查记录：`th16.exe` 可以按模块 RVA 读取；本机另有 `th16c.exe`，
其运行时内存布局不同。使用者确认在日文和汉化使用方式下均可修改资源；
当时实际运行的进程为 `th16.exe`，因此这项结果适用于该 EXE 的两种显示方式。
`th16c.exe` 仍是独立配置，不能直接复用 `th16.exe` 的地址。

阶段 2B 验证记录：TH16 日文版已完成受限范围写入、失败回滚和写后回读校验。
在实际关卡中以当前值原样写回，残机 2、Bomb 3、碎片 0、Power 1.00 前后一致。
界面支持四项分别应用，也可以一次全部应用；底层只写用户选择的项目。
运行反馈：四项内存数值都能按选择写入并回读，但游戏还有独立的界面和玩法
状态。残机/Bomb 的 HUD 可能延迟刷新；Power 面板虽然可立即变化，自机攻击
配置（例如灵梦的阴阳玉数量）可能要等几十秒或下次游戏内部资源事件才变化。
Bomb 也曾出现过延迟印象；两次只读记录证实修改后的 Bomb 可立即用于扣除，
且第一次 Bomb 从 7 回到 3 与残机、Power 同时下降，符合死亡重置。Bomb
仍会检查自身是否正在进行，HUD 则有独立刷新流程。当前“应用成功”只代表
内存数值已写入并校验，不能代表所有游戏内效果已同步。TH16 获得 Power 的
原生流程会额外调用攻击配置重建函数。后续若要即时同步，应在游戏主线程
执行对应流程并验证副作用；不能直接从外部线程调用未经验证的内部函数。

## 阶段 3：TH16 无限残机和 Bomb

- 无限残机、无限 Bomb 分别开关；碎片和 Power 保留直接修改，不提供无限锁定。
- 游戏正常执行消耗流程后恢复资源，避免使用超大数值造成溢出。
- 关闭开关后停止写入，不强制改变用户当前资源。

实现记录：开发版提供残机和 Bomb 两个独立“无限”开关，每 100 ms 只恢复已勾选
项目到输入框中的目标值。切换进程、取消勾选或退出工具都会停止锁定；碎片和
Power 仍可分别修改或随“全部应用”一起修改。

运行验证：在实际 TH16 日文版关卡中启用残机锁定并持续执行多个定时周期，开关
保持启用、写入未报错，取消勾选后定时器停止。实际消耗资源后的恢复效果由人工
游戏操作继续验收。

## 阶段 4：TH16 完全无敌

- 跳过敌方弹幕导致的受击状态切换。
- 保留擦弹、道具收集、射击、炸弹和正常画面。
- 保存并恢复被修改的原始指令。

开发版候选实现：已验证日文版 EXE 的三个碰撞路径最终调用同一受击状态切换函数
（RVA 0x43F10）。启用时先校验入口原始字节，再将首字节临时改为 `RET`；
取消勾选、切换进程或关闭工具时恢复。已在本机实际启动的 TH16 日文版进程中
验证补丁写入与恢复成功。使用者随后确认 TH16 日文版关卡中的无敌效果正常；
擦弹、射击、炸弹和录像行为尚未逐项验收，因此界面仍标为“实验”。练习录像
可能不同步。

## 阶段 5：逐作扩展

优先覆盖本机已有且能实测的作品。每增加一作，都重复版本识别、资源读写、
无限资源、无敌和恢复测试。TH09、TH10、TH11、TH19 等特殊资源系统单独设计界面语义。

按用户要求加快基础资源适配：TH14、TH15、TH17、TH18、TH20 本机 `thXX.exe` 的确切
SHA-256 已加入同一套直接数值配置。可读取并分别修改残机、Bomb、Bomb 碎片
和 Power，写后回读校验。碎片专指 Bomb 碎片；不提供残机碎片设置。
地址参考下方 thprac 提交，以模块 RVA 定位。
这些都是尚待实际关卡核对的开发版候选功能，不能称为已验证适配；无限和
无敌也尚未开放。汉化版仍须单独识别，不能仅按游戏编号复用地址。
启动后只读检查：TH14、TH15、TH17、TH18 在标题画面返回全零；这只验证
访问通路，不验证关卡实际数值。TH20 标题画面读数超出合理范围，已被校验
阻止；需要进入关卡后区分“尚未初始化”和“地址不匹配”，在此之前不计为
读取通过，更不能声称写入有效。

关卡内人工反馈：TH14、TH15、TH17 的残机、Bomb 与 Bomb 碎片修改均可用；
Power 面板数值可修改，但攻击配置未立即同步。死亡后游戏按自身规则扣除
Power，并重新计算攻击，届时阴阳玉数量与新的 Power 档位一致。这说明
当前写入的是资源数值，而非同时触发游戏内部攻击配置重建。三作都出现同类
现象，不能再将其视为 TH16 独有问题。当前不采用从外部线程调用游戏内部
函数或直接覆写攻击缓存的办法；找到可验证的主线程刷新入口后再考虑修复。
